# CTMC CGI 车载数据服务

线上入口：[quality-ctmc.cloud/vehicle/](https://quality-ctmc.cloud/vehicle/)，也可从质检主页第 05 个业务模块进入。使用现有平台账号；管理员默认新增 vehicle 权限，其他账号由用户管理显式授权。

## 已实现

- GPCHCX 46 字段解析、XOR 校验、十六进制状态/告警、GPS 时间转 UTC，前端统一北京时间。
- SN 自动建档，独立车辆/车队资料、规则和事件。公网 IP 变化不改变设备身份。
- 设备与时间范围查询、高德国内底图（GCJ-02 展示，原始数据 WGS84）、轨迹首尾、回放速度、时间滑块、断档/跳点断线。
- 12 组惯导图表：姿态、三轴角速度、三轴比力、三向速度、位置/姿态/速度标准差、平面速度、高程、卫星数、差分延迟、航迹角。时间缩放与过滤后的有效峰值包络；不可用字段不补零。
- 运行总览和惯导分析提供完全一致的筛选时段 10 Hz 低频振动趋势：短时使用原始显示桶，长时使用 60 秒/10 分钟派生桶，展示动态 RMS、峰值偏差、峰峰值和有效样本数；两页都在同一组件中使用筛选末端连续约 60 秒原始窗的诊断频谱，不新增振动原始数据落盘。
- 定位质量、惯导未就绪、设备告警、差分延迟、精度、时间断档/倒序/位置跳变，以及有质量门槛的超速、急加减速、姿态/冲击候选事件。
- 连续事件合并、定位到有效采样、确认/关闭与审计。历史事件保留规则版本；隔离原值和原始报文核验集中于数据质量页。
- 速度积分估算里程、运动时长、停留/行程区段、固定解占比、有效数据 CSV 导出、接入与磁盘质量面板。
- 独立离线解析工作台：上传与“导出有效数据”同字段的 CSV/CSV.GZ，重建轨迹、行程与停留、异常候选和 12 组惯导图表；不写入在线采样、设备、事件或审计库。
- 静止事实按 SN/配置分段隔离，支持显式持续静止状态、管理员关闭、组合导航下的高置信低速持续运动自动退出、MAD 稳健阈值、字段级异常台账与原报文追溯；详情见 [静止数据过滤说明](docs/静止数据过滤说明.md)。

## 结构

```text
CGI 设备 → 原有 TCP :9000 → 原始日志（原服务完全保留）
                              ↓ 只读增量/游标
                     新车载服务 :8790（仅回环）
                              ↓
                   独立 SQLite WAL 数据库
                              ↓
                  现有 nginx /vehicle/ 路由
                              ↓
                   平台会话 + vehicle 权限
```

`vehicle/protocol.py` 协议；`store.py` 入库、规则、查询；`rules.py` 业务规则判定；`quality.py` 过滤与冻结参考；`server.py` 认证与 HTTP；`static/` 页面；`tests/` 真实报文和合成边界测试；`deploy/` 部署与回滚；`integration/` 现网最小挂载工具。

## 运行与验证

需要 Python 3.11+。服务端无第三方 Python 依赖，前端 Leaflet 1.9.4、ECharts 5.6.0 静态文件已固定版本，许可证保存在 `static/vendor/`。

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
python3 -m vehicle.server --raw /path/to/raw --db data/vehicle.sqlite --auth http://127.0.0.1:8010
```

实际 API 不提供匿名/测试登录。`tmp/preview.py` 仅为本次本机只读视觉验收，不在部署包内。

## 重要边界

当前实际接入的是 GPCHCX（设备 6094510），GPCHC 基础解析器要求显式设备绑定；无 SN 的基础报文在采集中隔离并统计，不能依公网 IP 自动归属。辅助 ASCII 只核验校验和并计数；未知二进制未解码，原文件仍保存。

SN 是逻辑身份，不是密码鉴权。当前接收器为公网原始 TCP，多设备正式运营应使用专网/VPN或认证网关。默认模块授权可查看所有接入设备；车队字段用于分类，不是租户权限隔离。

原始坐标按 GNSS 默认 WGS84 使用；高德底图覆盖物统一在前端转换为 GCJ-02 展示，数据库保留原始 WGS84，过滤后的导出和里程计算亦使用 WGS84。显示转换不用于厘米级测量。详见 [大陆底图修复](docs/大陆底图修复.md)。加表单位 g、陀螺单位 °/s 依据手册同类 IMU/CAN 定义及实际静态重力量级采用；上线运输业务前应结合设备输出配置和安装标定复核。

地图瓦片使用 OpenStreetMap 公开服务，显示署名并按正常视口加载，无预下载。受外网可用性和服务政策限制；正式规模部署应换为有服务保障的合规地图服务，并明确坐标转换。

本系统为工况分析试运行版，不是 JT/T 808 协议终端或通过 JT/T 796 认证的监管平台。车辆业务阈值是工程起始值，不是法规统一阈值。没有司机身份/CAN/油耗/道路限速输入时，不输出疲劳驾驶、油耗或真实道路违法结论；没有 ISO 2631 频率加权与合适安装条件时，不输出人体振动舒适度等级。

振动分析受 10 Hz 输入的奈奎斯特上限约束，只展示保守的 0–4 Hz 低频载体振动。运行总览和惯导分析的筛选区间曲线都读取同一份聚合桶统计（不以聚合桶重建频谱）；两页的末端诊断 FFT 都只使用筛选末端连续原始窗。两者都不对缺测插值，也不用于轴承、齿轮等通常需要 kHz 级采样的机械故障诊断。设备在 10 Hz 输出时的抗混叠特性尚未由厂家资料或实测确认，因此 FFT 只作趋势观察。三轴合成模长后做线性去趋势可降低安装方向影响，但不等同于已获得车体系线加速度或严格去重力。

图表单次最多查询 31 天：6 小时以内读取原始采样，6 小时至 2 天使用 60 秒派生聚合，2 天以上使用 10 分钟派生聚合，首尾不足一个聚合桶的部分仍读取原始采样。每个设备、每个分辨率都必须与设备累计点数一致且版本有效；未就绪时仅在原始数据不超过 100 万条时安全回退，否则明确拒绝。长窗口不再对原始表执行全量计数。CSV 最多导出 10 万条，异常原值超过 100 万条需分段查看。两层聚合均保留过滤后均值、最小值、最大值、三轴比力合成模长的 min/max/sum/sum-of-squares/count，以及轨迹断点和运动摘要，原始采样仍是唯一事实来源。按当前约 10 Hz 估算，单设备连续 10 天约 864 万条原始采样，查询只需合并约 1,440 个十分钟桶并输出至多 360 个图表桶。持续多车 100 Hz 最终仍应升级分区时序存储和归档任务。已配置每小时容量检查：达到 80% 后按旧到新清理车载原始日志及关联采样和各层聚合，目标降至 75%，保护最近 24 小时及活动文件。详见 [存储清理说明](docs/存储清理说明.md)。

离线解析与在线导出使用同一 CSV 字段契约。单文件只允许一台设备、最长 31 天、最多 3,000 万行；原始 CSV 上限 12 GiB，CSV.GZ 上限 1 GiB。10 天约 864 万行，建议先用 `gzip 原文件.csv` 得到 `.csv.gz` 再上传。服务从 nginx 到 Python 解析器全程流式读取，以最多约 1,600 个自适应源桶控制内存；10 天采用 10 分钟源桶，页面仍输出至多 360 个展示桶并保留各字段最小/最大包络。大文件解析可能持续数分钟，期间不要关闭页面。上传结果只存在于该次响应及当前浏览器页面。
