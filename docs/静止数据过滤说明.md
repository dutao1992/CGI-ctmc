# 静止数据过滤与异常隔离 v3

## 事实、坐标切换与作用域

用户确认 CGI 模块一直原地未移动。过滤仅绑定 **SN 6094510**，分成三个连续事实区间：

1. 2026-08-26 15:08:55.100—18:39:57.900：首次冻结参考；
2. 2026-08-26 18:39:58.000—2026-08-27 09:59:56.900：设备仍侧放，独立拟合旧坐标参考；
3. 自 2026-08-27 09:59:57.000 起：参数设置生效后的持续静止状态，直至操作员关闭或系统确认高质量持续运动后自动关闭。

第三段不能沿用旧参考。实测切换前后横滚约从 `-90.26°` 变为 `-0.25°`，重力主轴从 X 轴变为 Z 轴；新参考中心为 pitch `0.44°`、roll `-0.25°`、`ax/ay/az=0.0044/0.0076/0.9970g`。这说明安装角补偿已经进入输出链路。

持续状态是用户提供的运行事实，不由“IMU 看起来安静”自动建立。常速车辆也可能有安静 IMU，因此其他 SN 不继承。系统只允许用完整的高质量持续位移证据撤销这一事实；关闭后的真实运动不再套用静止规则。原始 `points` 与报文不改写；`point_quality` 仅存版本、上下文、字段掩码和原因，异常是逻辑隔离而非物理删除。

## v3 算法

1. **状态提示而非过滤**：导航初始化、定向未就绪、静止或低速航迹角只记录为状态提示，原始参数不置空、不因状态本身造成曲线断点。无定位（`valid_pos=0`）仍不绘制坐标轨迹，以免凭无效坐标制造路线；其他惯导和质量字段继续保留。
2. **配置分段基线**：每次设备坐标、安装角或物理安装改变后单独拟合，不跨配置混合。中心使用中位数，尺度使用 `6×1.4826×MAD` 和工程噪声下限；姿态使用环形角差。
3. **唯一剔除规则**：确认静止段内，有效定位到锚点的球面距离超限，或水平定位标准差超过该静止参考上限时，只屏蔽经纬度。新持续静止段把径向上限封顶为 **15m**；`lat_std/lon_std`、速度、姿态、角速度、比力和航迹角仍保留，便于复核与曲线分析。
4. **统一运行投影**：采样先写原始表和质量索引，再由唯一的 `quality.project()` 投影。设备最新状态、查询、12 组曲线、地图、运行统计、业务事件门控和默认 CSV 都使用投影值；待判定数据失败关闭，不进入运行界面。
5. **地图与里程**：被剔除经纬度的静止漂移不连接轨迹，只在稳健锚点标示静止位置；静止速度不累计里程和运动时间。连续源桶的首尾轨迹点均保留，长时间筛选由前端在相邻连续锚点之间做显示插值；空值不补零、不插值测量值。

阈值是本项目针对确认静止设备的工程门槛，不是交通法规强制限值，也不能证明传感器故障。位置仍以天线相位中心为参考；单点或 RTK 浮点不能按厘米级真值解读。

## 参数后最新状态快照

截至本次升级前的最新 10 分钟约 6,001 条采样：

- 主要状态为 `91`：卫导模式、RTK 浮点、未定向；短暂出现 `71`、`61` 和 `00`；
- warning 为 `0x0002`，按手册属于 PPS 保留位，不作为已确认硬件故障；
- pitch 中位数约 `0.45°`，roll 中位数约 `-0.25°`；三轴角速度稳定在零附近；
- 速度中位数 `0.05m/s`，但存在约 `1m/s` 静止假速度；位置和高程仍有明显漂移；
- `lat/lon` 标准差中位数约 `3.23/3.56m`，95 分位约 `13.10/12.45m`，定位质量不稳定；
- 尚未出现组合导航状态 `nav_mode=2`，RTK 固定解占比仍为 0%。

因此安装角修正有效，但差分只达到浮点且组合导航未就绪。算法可以阻止漂移污染运行页面，不能替代设备侧完成固定解、定向与组合对准。

## 页面、证据与生命周期

- 运行总览、惯导分析、设备快照、运行事件和“导出有效数据”只读过滤投影；
- 数据质量页按原因分页展示异常原值、参考、阈值、源文件偏移和原报文核验；
- `/api/point` 默认过滤，只有质量台账显式 `view=raw` 读取原值；
- `/api/export` 默认过滤，`view=excluded` 导出隔离证据；
- 持续静止上下文在页面显示“持续静止 · 自动防护”。管理员可在数据质量页填写北京时间和原因，在设备出发前关闭；接口只接受不早于最新采样的边界，关闭立即生效并写审计，不需要重启服务。
- 若操作员漏关，系统有两条独立自动退出路径。**低速小推车路径**：`nav_mode=2`、`fix_mode∈{4,5,8,9}`、水平定位标准差不大于 1m、原始速度不小于 0.15m/s、离锚点至少 `max(30m, 2×静止半径)`，持续至少 15 秒/10 点、净位移至少 8m、轨迹有效率不低于 50%。**车辆路径**：`nav_mode∈{1,2}`、同样只接受 RTK 固定/浮点、水平定位标准差不大于 5m、速度不小于 1m/s、速度与水平速度向量相符、连续至少 10 秒/20 点、净位移至少 25m、轨迹有效率不低于 65%，并且坐标净位移为速度积分的 65%—135%。两条路径均拒绝单点跳变、低质量定位、原地往返或只有速度尖峰。
- 低速条件支持最高约 0.5m/s 的小推车；以当前 15m 静止半径和 50m 连续路线计算，通常在总行程约 38—45m 时确认，停顿或导航降级会重新计时。
- 自动关闭发生在候选起点前 1ms；完整证据窗确认后，候选窗质量投影和相关聚合桶立即重算，因此不会丢失行程开头 10—15 秒。自动判据、路径类型、样本数、持续时长、净位移、路径长度、速度积分距离、二者比值、轨迹有效率、速度范围和定位状态均写入审计。
- 已经发生的历史误过滤仍使用命令行显式补关并回算：

```sh
python3 -m vehicle.quality --db /srv/ctmc-vehicle/data/vehicle.sqlite \
  --close-context 313231eee2fbe7c44784 --close-end <开始移动前的Unix秒> \
  --close-reason '<操作员和原因>' --backfill
```

关闭操作只截断作用范围，原始采样和审计保留；后续发布不会从打包清单静默重新打开它。自动关闭是运营漏操作的保守兜底，不能替代出发前检查。

## 发布、验证与回滚

发布脚本停止车载解析服务和留存定时器，但不停止 TCP 9000 接收器；先做 SQLite 一致性备份，再核对三个训练区间、安装上下文、回算 v3、比较原始记录 SHA256 和 `quick_check`，最后切换 release。失败自动恢复旧 `current` 和 systemd 单元。不得用旧数据库覆盖发布期间继续接收的报文。

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_map.cjs
```

容量清理仍使用 80% 触发、75% 停止、最近 24 小时保护策略；删除原始采样时在同一事务删除关联质量索引，设备资料、上下文和审计保留。
