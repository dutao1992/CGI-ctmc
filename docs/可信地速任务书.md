# 目标

按 CGI-430 V2.4.4 手册和线上原始 GPCHCX 数据，统一总览、惯导曲线、统计、里程、导出的可信水平地速。原始 V_2D 不是轮速；低振动不等于静止。

# 完成标准

- 原始 52.344 km/h 解算异常不进入有效速度；不伪造实际推车最高速度。
- 可信匀速即使比力模长为 1 g 也保留；重复导航解算不因零坐标差被删。
- 持续低速、低不确定度且 IMU 安静才输出静止 0；无法判定留空。
- 入库与历史重算共用有界因果窗口；重启、分桶、导出离线口径一致。
- 最小测试先失败后通过；全量回归、线上历史回放及部署后资产/API 验收通过，提交 Git。

# 禁止事项

不改原始 points、接收日志、设备配置、报警业务阈值或振动算法；不积分加速度或相邻漂移位置造速度；不把设备标准差称为实测误差或独立真值；不将 0.01 g 单点阈值继续当作停车证明。

# 执行步骤

1. 核验手册协议、线上版本、时间覆盖、真实异常和正常对照。
2. 固定新验收样本并在修改算法前运行。
3. 增加可重算的可信地速判定和版本化投影，接通聚合、导出、前端说明。
4. 运行相同测试、全量回归和逐日只读回放；记录覆盖率与缺测，不以降低最大值作为唯一验收。
5. 使用现有部署流程，备份数据库、迁移派生数据、验收线上，提交 Git。
6. 2026-09-03 迁移性能事故补充：先恢复旧版查询；以 SQL 步数测试复现并修复前驱查询及批次重扫。在独立 SQLite 副本完成全量预计算，旧版继续服务；核验原始摘要一致后仅安装派生表，禁止用旧快照覆盖原始表、游标、用户标注。每批输出已提交进度；上线失败从备份恢复旧派生表，避免再次全量重算回滚。

# 验收方法

`python3 -m unittest discover -s tests -v`；`node --test tests/test_map.cjs tests/test_chart_peaks.cjs`；专门地速测试；只读生产数据库回放；部署后 current、静态资源指纹、healthz、质量/聚合版本和指定历史窗口查询。

# 风险

缺乏轮速/外部真值，无法保证每个 GNSS 速度代表真实运动；严格质量门控会增加缺测。因果判定有短暂预热。数据质量版本升级需重算已有约 226 万点和两级聚合，API 维护时接收器必须持续落盘。

# 回滚方案

副本预计算失败不停止旧版 API。切换或验收失败时停止新解析/API，保留 TCP 接收器；原始摘要相同时用 `prepare-quality.py --restore-from` 恢复备份中的旧派生表并切回旧 release。若原始数据已继续增长，拒绝强制覆盖快照，在解析停止时运行上一 release 的 `python3.11 -m vehicle.quality --db /srv/ctmc-vehicle/data/vehicle.sqlite --backfill` 重建旧版本派生数据后重启。补读维护期间日志，不覆盖原始库、游标和用户事件标注。保留新旧 release、压缩备份路径和原始摘要供核对。
