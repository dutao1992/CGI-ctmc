## 审计结论

1. **P1 数据中断**：解析/API 服务正常，但设备已连续数天无有效报文。应先检查 CGI-430 供电、移动网络、服务器地址/端口和协议输出配置。
2. **P1 接入安全**：TCP 9000 监听公网、无设备鉴权，主机防火墙为全放行。SN 只是逻辑身份，攻击者可探测端口，也存在伪造合法帧和 SN 的数据污染风险。不能在不知道设备固定出口的情况下盲目加 IP 白名单，应由业务选择专网/私有 APN、VPN 或具有设备密钥的认证网关。
3. **P2 最小权限**：主服务当前以 root 运行，原因是原始接收目录为 root-only。本轮增加 systemd 进程隔离，但完整解决仍需先为原始目录设计专用组/ACL，再迁移到专用服务账号。
4. **P2 容量治理**：生产有 28 个发布目录和约 1.4 GiB 备份。这些包含回滚证据，本轮不自动删除；应由用户确认发布与备份保留数后再实施白名单清理。
5. **P2 数据库深度校验**：生产 `PRAGMA quick_check` 在 50 秒内未完成，为避免持续占用已主动中止。这不是损坏证据；聚合计数、WAL 和待处理关系检查均正常。完整校验应改为业务低峰独立执行。

## 已实施优化

- 解析器在有真实采样时保持 1 秒延迟；无有效点或仅有公网探测时逐步退避到 5 秒，降低 4,329 个原始文件重复扫描带来的空载 CPU。
- `/healthz` 改为只读心跳与错误元数据，不再执行详细统计；认证响应和 CSRF 令牌改为严格类型验证，并减少 Python 版本信息暴露。
- 补充 Permissions Policy、同源资源策略和 CSP `form-action`；systemd 补充个性固定、禁止可写可执行内存、命名空间/实时调度限制与本机系统调用架构。
- 聚合已完整时跳过部署停机窗口中的全库 `quick_check`；设备累计数和原始点数不一致时拒绝重建，避免用派生结果掩盖基础计数漂移。低峰完整性核验可显式加 `--verify-current`。
- 顶部状态区分“采集服务异常”、“服务正常但等待设备”、“服务正常但设备无新数据”与“采集和设备数据均正常”，避免把解析心跳误当成设备在线。
- ECharts 从 5.6.0 升级到 6.1.0，更新 SHA-256 固定值并为 Leaflet、ECharts 与坐标转换脚本统一加入内容指纹缓存参数。
