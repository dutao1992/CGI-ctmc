# CGI 车载数据服务实施任务书

## 目标
在 quality-ctmc.cloud 的现有登录和权限体系下新增车载数据服务，从已运行的 9000 TCP 接收器旁路读取真实数据，支持多个 CGI 设备。

## 完成标准
按 SN 隔离设备；校验 GPCHCX/GPCHC 报文；保留原始文件定位证据；设备与时间范围可筛选轨迹、回放、惯导曲线、异常事件、行程统计；设备资料和规则可管理；主页入口和独立权限生效。真实样本、异常样本、断点恢复、未授权访问和主页回归必须验证。

## 禁止事项
不修改、不重启 9000 接收器，不改设备设置，不删除历史原始数据，不改变既有模块和账号权限，不把模拟数据混入生产，不宣称通过 JT/T 标准认证，不把缺少司机身份和工况的推断当作疲劳驾驶结论。

## 执行步骤
1. 核验现网、协议、样本及手册；备份将修改的门户入口、权限文件和 nginx 配置。
2. 在本目录建立独立 Python/SQLite 服务和可恢复只读文件采集器。以 SN 识别设备；无 SN 的 GPCHC 留待明确绑定，不按公网 IP 合并设备。
3. 实现历史与增量接入、数据校验、异常规则、查询/导出、设备与事件管理。设备时间转换到 UTC，界面统一北京时间。保留单位、采样/降采样说明。
4. 使用 frontend-design 实现深绿工业仪表界面：地图与回放联动、惯导曲线峰值包络、异常时间定位、设备/规则和数据质量说明。
5. 新服务仅监听本机；接入平台会话和独立 vehicle 权限；主页新增第 5 个入口，保持原模块资产不变。
6. 运行测试后隔离部署，验收未登录拒绝、真实数据查询、浏览器操作和原系统健康。

## 验收方法
通过 unittest 验证真实校验和、分片粘包、未知/坏数据、十六进制状态/告警、GPS 闰秒转换、设备隔离、断点幂等、事件质量门槛、查询和权限；使用现有 npm test/build 检查门户。上线后检查采集心跳、数据库增长、API 数据、401/403、地图和曲线，并记录具体结果。

## 风险
当前设备为卫导单点未定向，不能称厘米级结果；横滚约 -90°，必须先确认安装标定再启用车身姿态业务预警。原始流混有其他 ASCII 和未公开二进制，未知协议只留档。公网 TCP 没有设备密码身份认证，SN 仅逻辑身份；若未来需要可信鉴权应加 VPN/认证网关。10–100 Hz 长期原始留存需要容量规划，不擅自清理。地图瓦片依赖外网，失败时仍显示轨迹坐标和曲线。

## 回滚方案
单独停止新 vehicle 服务；恢复备份的门户 index、权限文件和 nginx 配置，先 nginx -t 再 reload；仅在权限文件回滚时重启平台 API。新数据库和原始接收文件保留。原接收 PID、配置、原业务数据库不在变更范围内。

默认决定：面向运输工况分析，先提供规则预警而非法律违规认定；所有新设备默认未确认安装姿态。新模块权限仅管理员自动拥有，普通账号由现有用户管理显式授予。
