# 中国大陆底图访问修复

## 目标
解决手机在大陆网络无法加载 OSM 底图的问题，保留原有轨迹、回放、事件定位和原始测量数据。

## 完成标准
替换为高德 HTTPS 道路底图；大陆服务器多节点、多缩放级别实际返回 PNG。轨迹、起终点、事件点、回放、曲线联动和事件定位共用 WGS84 → GCJ-02 显示适配。原始坐标读数、数据库、CSV、里程计算保持 WGS84。

## 禁止事项
不改设备/接收器，不修改存储清理阈值，不改历史测量坐标，不混用不同坐标系的底图和覆盖物。不使用别人的 API Key，不代理或规避被拒绝的服务访问。

## 执行步骤
1. 核验图源网络和坐标系；大陆服务器已对高德四个域名、11/15/17 级共 12 个请求验证，均 HTTP 200 且为 PNG，约 60–122 ms。
2. 本地固定 coordtransform 源码及 MIT 许可，页面不依赖第三方 JS CDN；来源和 SHA256 见 map-vendor-manifest.json。
3. 添加统一的地图显示适配器，替换所有落点；更新 CSP 精确域名白名单、图源版权和坐标说明、资源指纹。
4. 测试后发布并验证真实页面；只切换新车载服务，不改现有 TCP 9000 接收服务。

## 验收方法
`node --test tests/test_map.cjs`：公开参考点、坐标轴顺序、不修改原数据、不重复偏移、范围外处理、失败瓦片提示、真实 app 渲染/回放/联动路径。`python3 -m unittest discover -s tests -v` 保持原 34 项测试。正式页面检查图片 naturalWidth、错误提示、无 OSM 请求、手机窄屏显示。测试不等同于用户每个运营商网络的实测。

## 风险
高德底图为 GCJ-02；本地开源算法用于显示近似转换，不提供厘米级坐标转换精度。算法范围判断是矩形近似，境外/边境场景需另行核验。本次不改变 GNSS 数据按 WGS84 解释的前提。公开瓦片服务没有本项目专属 SLA，不宣称获得商业授权或无限配额；规模化生产应按供应商条款配置正式服务。底图只请求视野瓦片，不向地图商上传设备 SN、报文或完整轨迹。

## 回滚方案
发布前版本为 `/srv/ctmc-vehicle/releases/20260826-192810`。发布脚本失败会恢复上个 current 和车载服务；数据无需回滚。若需人工回退，暂停车载清理单元后恢复 current 链接、车载 service，重新启动并启用原清理 timer；不重启接收器。

## 依据
- [高德坐标系及转换说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)：高德坐标为 GCJ-02，GPS 坐标需转换后叠加。
- [阿里云 DataV 底图接入说明](https://www.alibabacloud.com/help/zh/datav/datav-6-0/user-guide/bottom-layer)：列出高德公开瓦片服务及 style=7 道路图层；本项目使用实测可用的 HTTPS webrd 节点。
- [coordtransform 原作者仓库](https://github.com/wandergis/coordtransform)：本地固定源码及许可，不依赖在线库脚本。
