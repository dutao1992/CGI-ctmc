# 聚合算法数据质量评估

> 核心问题：**当前聚合算法是否会把数据中的真实异常点（峰值/冲击/离群）屏蔽掉？**

---

## 结论摘要

| 评估维度 | 结论 |
|---|---|
| 均值是否吃掉峰值？ | **不会**。每个聚合桶同时保留 min/max/mean，前端展示峰值包络 |
| 过滤是否先于聚合？ | **是**。每条原始采样入库时即写 `point_quality`，聚合只读 `project()` 后的有效值 |
| 异常原值是否被删除？ | **不会**。原始 `points` 表永不修改，异常标记写到 `point_quality`，可完整追溯 |
| 事件检测是否基于原始采样？ | **是**。实时事件在逐条 `_point()` 时触发，离线事件逐行扫描 CSV，均不经聚合 |
| 聚合后能否反查异常？ | **能**。`quality_records` API 直接查询原始+质量联表，绕过聚合层 |
| 静止过滤是否会覆盖运动异常？ | **仅隔离经纬度**。确认静止段内只有定位偏差超限的经纬度被隔离，初始化/未定向/低速航迹角及其他参数仍保留 |

---

## 详细分析

### 1. 数据流水线架构

```
原始TCP报文
    ↓
FRAME 正则 + XOR/CRC校验
    ↓
parse() → 字段范围硬约束
    ↓ 写入 points 表（原值，永不修改）
    ↓
write_assessment() → point_quality 表（版本化标记）
    ↓
project() → v3按字段隔离（仅静止定位偏差的经纬度置None，不删行；状态提示不屏蔽字段）
    ↓
RollupBuilder.add() → 每60秒桶: 常规字段 min / max / sum / count / last；振动合成模长 min / max / sum / sum-of-squares / count
    ↓
QueryCombiner → 跨桶合并 → 前端图表
```

**关键设计**：过滤（`quality.project`）发生在聚合之前的每条采样上，而非批量平均后。

---

### 2. `RollupBuilder` —— min/max 保护机制

```python
# aggregate.py L96-104
for metric in METRICS:
    value = p[metric]
    if value is None:        # ← 被过滤的字段跳过，不影响聚合
        continue
    a = self.metrics[metric]
    a[0] = value if a[0] is None else min(a[0], value)   # ← min
    a[1] = value if a[1] is None else max(a[1], value)   # ← max
    a[2] += value   # sum
    a[3] += 1       # count
    a[4] = value    # last
```

- 每个60秒聚合桶保留：**最小值、最大值、均值（sum/count）、最后一个值**；振动合成模长另保留 **min / max / sum / sum-of-squares / count**，用于筛选时段 RMS 与峰值偏差趋势
- 前端 `buildChart()` 同时绘制 mean（深色线）、min/max（浅色包络）
- **一个桶内的单点冲击峰值体现在 max 上，不会被均值淹没**

> [!IMPORTANT]
> 冲击/急加速/姿态突变等短时异常在 60 秒桶的 max 包络中可见。**6 小时以内的短时间窗口直接读原始采样，根本不走聚合**（`resolution = 0` 分支，`store.py L448`）。

---

### 3. 质量过滤 —— 异常点的处理逻辑

`quality.project()` 的行为（`quality.py`）：

- **不删行、不修改 `points` 表**
- 只有确认静止段内定位偏差超限的 `lat/lon` 置为 `None`（仅在内存中）
- 导航初始化、定向未就绪、静止或低速航迹角只写入状态原因，不置空任何参数
- `valid_pos` 重新评估：位置字段被 mask 时置 0
- `stationary_context` 标识所属静止区段

被置 `None` 的字段在 `RollupBuilder.add()` 中跳过（`if value is None: continue`），**不进入均值/min/max 计算**。

> [!TIP]
> 这是 v3 的唯一字段隔离规则：被判定为“静止期定位漂移”的坐标不应混入运动轨迹的位置统计，但速度、姿态、角速度、比力和标准差等原值继续进入曲线，原始值始终在数据库中可查。

### 7. 筛选时段振动趋势的口径

运行总览的振动曲线复用当前筛选查询的原始显示桶或 60 秒/10 分钟聚合桶，不扫描全时间范围原始表，并与速度剖面使用相同筛选边界和悬停时间指针。每个曲线点为 `[时间, 桶内去均值 RMS, 桶内峰值偏差, 合成模长均值, 最小值, 最大值, 有效值数]`；聚合查询的首尾原始点与中间派生桶仍按同一口径合并。诊断频谱从筛选时段的连续候选窗口中选择去趋势动态 RMS 最大的名义 60 秒原始三轴窗口；长查询先用 60 秒聚合 RMS 排名候选，再回读候选附近原始样本核验，不由聚合桶重建 FFT。

10 Hz 输入的奈奎斯特频率为 5 Hz，页面将 FFT 显示带宽限制在 0–4 Hz。该链路用于低频载体振动观察与趋势取值，不等同于经校准的高频机械故障诊断；缺测、被过滤字段和不连续窗口不补零、不插值。

---

### 4. 事件检测 —— 完全在聚合层之外

实时路径（`store.py L519-557`）：

```python
def _point(self, c, p, stat):
    ...
    mask, reasons, context_id = quality.write_assessment(c, p, ...)
    p = quality.project(...)   # ← 这里过滤
    signals = conditions(p, state['prev'], baseline, rules, ...)  # ← 逐点触发
    for kind, (value, threshold, severity, dwell) in signals.items():
        self._event(c, p, state, kind, value, threshold, severity, dwell, rules)
```

- 每条采样逐一评估，**事件触发不依赖聚合桶**
- 急加速/急减速用 0.8-2.5 秒的滑动窗口内相邻原始点计算（`rules.py L53-60`）
- 冲击检测用合加速度 `sqrt(ax²+ay²+az²) - 1`（`rules.py L65-67`）

即使查询窗口 >6 小时走聚合路径，**事件列表仍来自原始逐点扫描的结果**（`query()` 最后调用 `self.events()`，后者直接查 `events` 表）。

---

### 5. 已确认静止过滤 —— 只隔离定位偏差

`make_active()` 激活后的定位参考限制：

```python
profile['position_limit_m'] = min(profile['position_limit_m'], 15.0)    # ← 上限 15m
profile['position_std_limit_m'] = 5.0
```

门槛设计保证：**只有已确认静止上下文内、定位偏离锚点或水平定位 σ 超限的点才会隔离经纬度**。初始化、未定向、静止/低速航迹角不会触发字段隔离；高程、速度、姿态、角速度、比力及其标准差也不会因为静止状态被置空。

潜在风险点（需持续关注）：

| 场景 | 影响 | 风险等级 |
|---|---|---|
| 设备确实在移动，但静止上下文未及时关闭 | 运动期间定位经纬度仍可能按静止参考隔离；速度和惯导曲线仍保留 | ⚠️ 中等 |
| `confirmed_stationary_active` 长期开放 | 若设备挪动后未手动关闭，定位经纬度仍可能按静止参考隔离 | ⚠️ 中等 |
| 静止区段内的 IMU 异常（陀螺漂移、比力突变） | 不再被静止质量规则屏蔽，继续进入曲线和事件复核 | ℹ️ 低 |

> [!WARNING]
> **优化落实（2026-08-28）**：平台已增加管理员手动关闭入口和保守的自动退出保护。自动退出不依据单个速度或 IMU 值，而要求高质量组合导航、RTK 固定/浮点、离开锚点及持续位移同时成立；证据写入审计。操作员仍应在设备出发前主动关闭，自动退出仅作为漏操作兜底。

---

### 6. 数据真实性验证路径

若怀疑某条采样被不正当屏蔽，可以：

1. **数据质量页** → 异常数据隔离台账 → 筛选“静止定位偏差”；初始化/未定向/低速状态在状态提示采样统计中查看
2. **点详情 API** `GET /api/point?device=SN&t=时间戳&raw=1` → 返回原始值 + 过滤决策树 + 原始报文偏移
3. **命令行验证** 按 `source_offset` 定位到原始 `.log` 文件的具体字节

---

### 8. 长窗口轨迹与回放

每个源时间桶保留首、尾两个有效定位锚点；合并 60 秒/10 分钟聚合时不再按展示桶折叠为单点，最多保留 20,000 个全窗口锚点。前端只在相邻、连续且非静止锚点之间对经纬度做回放插值；跨断档、显式轨迹断点或静止区段时回到邻近实测点，不制造路线。这样长时间筛选仍有足够回放锚点，且不改变曲线统计或原始数据。

## 需要改进的潜在问题

### 问题 A：heading/course 的 `last` 语义

```python
# aggregate.py L279
mean = last if metric in ('heading', 'course') else total/n if n else None
```

航向角和航迹角在聚合桶内取"最后一个值"而非均值，避免 0°/360° 边界引起的均值失真。  
**影响**：60秒桶内的航向变化只保留最后状态，中间的剧烈旋转不在均值中体现（但 min/max 包络仍可见）。

**风险等级**：低。min/max 仍然保留，且 6 小时以内的短窗口直接读原始采样。

---

### 问题 B：10 分钟聚合是 60 秒聚合的二次聚合

```python
# store.py L150-164: _rebuild_derived_rollup
# 用 QueryCombiner 合并 60 秒桶 → 10 分钟桶
```

二次聚合中 min/max 是多个 60 秒桶的 min/max 合并（取最小的最小、最大的最大），**不损失极值信息**。

---

### 问题 C：首尾回退到原始采样的边界处理

查询时间窗口的头/尾不完整的 60 秒或 10 分钟桶，回退读取原始采样（`store.py L459-467`）。  
中间完整桶读聚合。两段数据通过 `combiner.add(snapshot)` 合并，逻辑一致。

---

## 总体评价

> **当前聚合算法在数据质量保障方面设计合理，不会屏蔽真实异常的峰值信息。**

核心保障：
1. 过滤先于聚合，按字段隔离，不修改原值
2. 聚合桶同时保留 min/max，前端展示峰值包络
3. 事件检测在逐条原始采样层面独立运行
4. 6 小时以内直接读原始采样，完全绕过聚合

主要运营风险仍是 **`confirmed_stationary_active` 上下文未及时关闭**。平台现已通过“管理员显式关闭 + 高置信持续运动自动退出 + 完整审计”降低风险。自动退出已覆盖最高约 0.5m/s 的低速小推车，但仍要求组合导航、RTK 定位、30m 离锚、15 秒连续、8m 净位移和轨迹一致性；卫导漂移不会仅凭速度自动撤销静止事实。
