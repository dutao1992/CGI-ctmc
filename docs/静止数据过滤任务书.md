# 实时静止数据过滤升级任务书

## 目标

依据用户再次确认的 SN 6094510 持续静止事实和安装参数切换后的最新数据，把 VPS 新收到的采样先做字段级质量判定，再交给设备运行页；异常原值只在数据质量页和证据导出中出现。

## 完成标准

1. 新安装角生效后的姿态/重力基线与旧侧放基线分离，后续入站采样实时判定；运行页、图表、地图、统计、事件和默认 CSV 共享同一过滤投影。
2. 原始采样数和摘要不变，待判定及孤儿质量索引均为 0，SQLite `quick_check=ok`。
3. 设备仍静止时里程和运动时间为 0；未定向航向、初始化数据、漂移位置、假速度和超限惯导字段不进入运行通道，但健康字段保留。
4. 持续静止只绑定当前 SN，其他设备不继承；状态可由显式、留审计的关闭操作终止，后续发布不得静默重新打开。

## 禁止事项

不修改或重启 TCP 9000 接收器；不覆盖或删除原始报文；不在前端另写一套过滤算法；不把异常改成零或插值；不将 RTK 浮点冒充固定解、卫导模式冒充组合导航；不让当前静止规则套到其他 SN 或关闭后的真实运动。

## 执行步骤

1. 核对生产最新 20 分钟的状态、warning、姿态、比力、速度、位置标准差和时间新鲜度，定位安装参数切换点。
2. 冻结切换前补充区间和切换后新训练区间；算法升至 v2，增加持续静止上下文、位置/高程不确定度门槛及静止质量封顶。
3. 保持 `points` 不变，只升级 `point_quality`；采集时先写原值和判定，所有运行出口只调用 `quality.project()`。
4. 数据质量页显示持续状态、阈值、原因和原值；实现一次性关闭持续状态及防重新打开保护。
5. 本机测试、生产库副本回放、发布前备份、服务器测试、切换、API/前端/新入站采样验证。

## 验收方法

运行 Python 与 Node 全套测试且 skipped/todo 为 0；在生产数据库副本执行 `prepare-quality.py`，核对 raw SHA256 前后相同、pending/orphan 为 0、`quick_check=ok`；部署后比较运行 API 与 raw evidence 同一采样，确认命中字段在运行值为 null、证据页仍为原值；等待新采样进入并确认版本为 v2；检查服务 NRestarts、9000 PID/指纹和留存定时器。

## 风险

持续静止状态若未在车辆移动前关闭，会把真实运动当异常；定位门槛会在当前 RTK 浮点不稳定时形成较多图表空缺，这是数据质量结论而非服务丢包。SQLite 全量回算会造成短时只读服务停顿，但独立接收器继续写原始日志。配置再次改变时旧参考会失效，必须建立新分段基线。

## 回滚方案

发布前保留一致性 SQLite 备份和旧 release；发布脚本失败自动恢复旧 `current`、车载服务和留存 timer，不动接收器。上线异常时先切回旧 release 并重启车载服务；不使用旧数据库覆盖新到报文。v2 新表结构兼容旧代码，质量索引可以从未改写的 `points` 重新计算。
