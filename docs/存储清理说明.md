# 车载数据存储清理

## 生效策略

由服务器 `ctmc-vehicle-retention.timer` 独立执行，不依赖网页打开或本机 Codex 在线。

| 项目 | 默认值 |
| --- | --- |
| 检查周期 | 每小时整点，随机延后最多 60 秒；开机补检查 |
| 触发条件 | 原始日志与数据库所在文件系统实际使用率 ≥ 80% |
| 停止目标 | 使用率 ≤ 75%；未到目标则后续检查继续 |
| 保护期 | 至少最近 24 小时，按完整文件/接收日期清理，实际可能更长 |
| 清理顺序 | 接收日期、文件最后写入时间，从旧到新 |
| 单次预算 | 最长约 10 分钟，systemd 12 分钟硬上限；超时可续作 |
| 白名单 | `/srv/chcnav-cgi430/logs/raw/YYYY-MM-DD/*.log` 及车载 SQLite 对应采样/过期事件 |

占用率分母为“已用 + 普通用户可用”，与 `df` 口径一致；页面显示小数，`df` 整数会向上取整。两条数据路径必须在同一文件系统，不满足则拒绝清理并提示检查。

## 保护与不可恢复边界

- 当前日和保护截止日目录不清理。文件或关联采样在最近 24 小时新增/变更、接收器仍打开的文件不清理。
- 有未处理完整行或超过 8 KiB 积压的文件不清理；已冷却的无换行尾部残片可随文件过期，并记录丢弃字节数。不是将有效积压当垃圾删除。
- 禁止符号链接、多硬链接和跨文件系统文件。只按白名单解除文件名链接，不调用通配递归删除。
- 先持久记录退休文件标记，再删除原文件和分批删除关联采样；中断后续作，重启采集器也不会将已退休路径重新导入。已开始处理的单文件可能在低于阈值时完成一致性收尾。
- 设备名称、车队、规则、最后一次状态快照及操作审计保留。采样条数和最早时间反映当前保留数据；累计接收计数继续累计。完全早于剩余采样的旧事件删除，跨边界事件摘要保留；缺失的峰值采样返回明确错误，不冒用下一条采样。
- SQLite 提前启用 `auto_vacuum=INCREMENTAL`，分批删除后回收空闲页并 checkpoint WAL。不会到磁盘紧张时再复制整个数据库做全量压缩。原理参考 [SQLite PRAGMA 官方文档](https://www.sqlite.org/pragma.html#pragma_incremental_vacuum)。
- 其他质检业务、平台账号库、系统日志、接收器程序、备份和发布目录不在清理范围。车载数据不足以解除压力时返回失败并告警，不扩大删除范围。
- **删除不可撤回。** 此配置是用户指定的容量策略，不承诺任何行业法定保留期。需长期留档的数据应在清理发生前另行导出或异地备份。

## 检查、配置与停止

```bash
systemctl status ctmc-vehicle-retention.timer --no-pager
systemctl list-timers ctmc-vehicle-retention.timer --all
journalctl -u ctmc-vehicle-retention.service -n 20 --no-pager
cat /etc/ctmc-vehicle-retention.json
```

配置文件为 root 0600，键为 `trigger_pct`、`target_pct`、`protect_hours`、`max_run_seconds`；任务每次启动读取。受保护时间不可低于 24 小时，目标占用必须低于触发占用。没有强制绕过阈值的生产 CLI 参数。

只读评估（默认不删除、不写检查回执）：

```bash
cd /srv/ctmc-vehicle/current
/usr/bin/python3.11 -m vehicle.retention
```

正常手动检查，仍服从真实磁盘阈值：

```bash
systemctl start ctmc-vehicle-retention.service
```

停用自动清理：

```bash
systemctl disable --now ctmc-vehicle-retention.timer
systemctl stop ctmc-vehicle-retention.service
```

停用不会恢复已删除数据。若中断在单文件处理中，应查看检查回执的 `pending_files`，不要手工移除 `retention_files` 标记；恢复任务会完成收尾。代码回滚时先停用定时器，恢复已验收的 current 链接与车载 service；无需反向迁移 SQLite 增量回收模式。

## 可见结果与故障

车载页面“数据质量”显示磁盘占用、阈值、保护期、最近检查时间、本次删除文件/采样数量。超过 90 分钟无回执、空间不足或清理异常会显示提醒；服务异常也记录到 systemd/journal。未配置短信、邮件或离线推送，不能把网页提醒当作已发送通知。

`status=below_threshold` 且删除数量为 0 表示检查成功但无需清理；`target_reached` 表示本轮回到目标；`pressure_remaining` 表示旧数据不足或时间预算耗尽；`error` 表示本轮受安全条件/错误阻止，需要查看 warning。
