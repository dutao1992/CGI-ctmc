# GPCHCX 原始地速回滚任务书

## 目标

运行总览、惯导曲线、离线分析、最高速度、估算运行里程和有效运动时间统一使用 `GPCHCX.speed`（V_2D）。三轴振动判定为静止时只把派生地速置为 0；明显导航漂移点置为缺测，不把 `Ve/Vn`、标准差或短窗参考值用于估速。

## 完成标准

- 运动点的有效地速逐点等于同一条 `GPCHCX.speed`，静止点为 0，非 GPCHCX、待回算和明显漂移点为缺测。
- 里程只对相邻、连续、有效定位且两端均为运动的上述速度做梯形积分；有效运动时间只累计相邻连续且两端均为运动的时间。
- 在线原始查询、60 秒/600 秒聚合、离线 CSV 与前端使用同一口径；不再返回或绘制参考地速通道。
- 原始 `points`、原报文、振动分析、地图坐标转换、设备配置、事件/用户标注、独立 TCP 9000 接收器不变。

## 禁止事项

- 不用 `hypot(Ve,Vn)`、坐标差分、加速度积分、插值、平滑或上一点补值估速。
- 不因导航未定向、低速或速度标准差偏大就自动置 0；只有三轴合成峰值偏差 `|sqrt(ax^2+ay^2+az^2)-1| <= 0.01 g` 判静止后才置 0。
- 不修改现有未提交的 README、CGI-430 设置说明、可信地速算法说明和 AHRS 评估文件；不改振动图实现。
- 不删减或跳过测试，不放松漂移判据，不覆盖生产原始库、游标、事件、审计或用户标注。

## 执行步骤

1. 冻结基线：记录 Git 工作区、质量/聚合版本、Python 111 项与 Node 39 项测试结果；确认本地数据只有 GPCHCX。
2. 建立新的版本化投影：保留 `point_ground_speed` 作为可回算审计记录，但其值只能是原始 `GPCHCX.speed`、振动静止 0 或缺测；明显速度/位置漂移统一隔离出地速。
3. 保持聚合的连续性、定位和运动双端约束，删除参考地速指标；为 GPCHC 不进入速度剖面、运动原值、振动静止 0、漂移缺测、里程/运动时间增加回归测试。
4. 离线 CSV 继续携带版本化地速元数据，但严格校验其与原始 GPCHCX 和振动状态一致；前端恢复单一“GPCHCX 地速”曲线与对应说明，不改布局、配色和振动图。
5. 刷新静态资源指纹，运行完整测试、语法与差异检查；在生产库副本回算，核对原始行数/摘要不变、派生表完整、数据库 `quick_check=ok`。
6. 使用现有分阶段发布脚本部署；切换后核对 release、服务、留存 timer、healthz、TCP 9000 PID、新采样版本，以及典型静止/运行/漂移窗口的 API 结果。

## 验收方法

- `python3 -m unittest discover -s tests -v`：失败 0、跳过 0，测试数不少于 111。
- `node --test tests/test_map.cjs tests/test_chart_peaks.cjs`：失败 0、跳过 0，测试数不少于 39。
- `python3 -m compileall -q vehicle analysis deploy tests`、`node --check static/app.js`、`git diff --check` 全部退出 0。
- 副本和线上分别验证：运动样本 `effective speed == raw GPCHCX.speed`，静止样本 `effective speed == 0`，明显漂移样本 `effective speed is null`；`speed_reference*` 不在查询序列；原始主键、内容摘要不变。

## 风险

- 仅凭振动区分匀速运动与静止存在物理局限，低振动匀速点可能被置 0；这是本次明确回滚口径，页面必须如实说明为估算。
- 质量版本变化要求全历史派生地速和两级聚合重建；生产期间原始数据继续增长会使离线副本过期，切换必须按现有摘要校验失败关闭。
- 把位置跳变点的速度一并隔离可能损失少量真实急变点；仅使用现有保守“明显单步跳变”判据，不扩大阈值范围。

## 回滚方案

发布前失败不切换服务。发布后若测试、摘要、派生覆盖、健康检查或典型窗口任一不满足，停止新 API，使用发布脚本生成的派生表备份恢复旧质量/聚合数据并切回上一 release；若原始数据已增长，则在停止解析的短窗口用上一 release 重建旧派生表。始终保留原始报文、`points`、游标、事件、审计、用户标注和 TCP 接收服务。
