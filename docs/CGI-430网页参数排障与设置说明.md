# CGI-430 网页参数排障与设置说明

日期：2026-08-28。对象：SN 6094510、CTMC 车载数据服务。

**结论：优先恢复有效差分、双天线定向和正确的组合导航初始化，再调整安装参数与输出。单纯加大滤波不能把单点未定向数据变成厘米级组合导航。**

## 2. 操作前准备：先备份，确认实际安装

1. 设备停止参与控制、记录操作开始时间和 SN，在安全停放状态下配置。需要动态标定时，由合格人员在封闭、安全场地按实际载体流程进行，不在普通道路做突然加减速或转向。
2. 连接设备 Wi-Fi `GNSS-6094510`（以实际广播名称为准），打开 `http://192.168.200.1`。手册默认 Wi-Fi 密码为 `12345678`，默认网页账号/密码为 `admin` / `password`；已修改时使用现有凭据，不恢复出厂绕过。
3. 到【固件→固件信息】记录固件、算法及协议版本；手册 V2.4.4 是文档版本，不能据此认定机器固件相同。
4. 到【固件→配置文件】下载配置；【固件→标定文件】下载标定；必要时下载【系统日志】【用户日志】。命名带 SN、固件版本和日期。
5. 截图保存【惯导状态】【惯导配置】三块设置、【里程计】、【I/O 设置】和【网络设置→摘要】。分享时遮住账号、密码、IMEI 等信息。
6. 确认实际装了几根 GNSS 天线、GNSS1/2 分别接哪根、主机 XYZ 朝向、是否接 CAN 轮速。不得用界面示例尺寸替代实测。

配置/标定文件仅允许同固件版本导入（第 43—44 页）。不要一开始恢复出厂、清卫星数据或升级固件；这些不是当前问题的首选修复。

## 3. 先恢复网络和数据上报

### 3.1 使用 SIM 回传

路径：【网络设置→移动网络设置】及【摘要】（第 40 页）。

- 确认 SIM 正常且有流量、移动网络模块打开、拨号已连接。
- 开启网络模块/拨号的开机自启动；具体按钮以现有固件为准。
- 若未连接，检查 4G 天线、SIM 套餐及信号。断电后再装卸 SIM（第 24 页）。
- 不能获取差分源列表时，先检查这一层；不要反复猜 NTRIP 密码。

### 3.2 使用网线回传

路径：【网络设置→有线网络设置】（第 40、75 页）。

- 使用与真实路由器/接收端一致的 IP、掩码、网关、DNS，设备地址不得与其他设备冲突。
- 手册所述默认有线 IP 为 192.168.45.100；不能将有线 IP 配在 192.168.200.x 网段，它与配置 Wi-Fi 网段冲突。
- 手册标注该版动态获取暂不可用；不要套用其它产品的 DHCP 教程。
- 现有网络已通时，不为修复定位漂移而改 IP/网关/DNS。

### 3.3 保持平台上传通道正确

路径：【I/O 设置→TCP/UDP_Client7→连接/详细】（第 35—36、75—78 页）。如果已连接且页面不允许编辑，先记录现值，短暂断开后编辑再连接。

| 网页字段 | 当前平台建议 | 说明 |
|---|---|---|
| 开机自连接 | 勾选 | 避免重启后不回传 |
| 连接协议 | TCP | 与现有 9000 TCP 接收器一致 |
| 远程 IP | 47.116.139.4 | 这是数据接收服务器 |
| 端口号 | 9000 | 不改成差分端口 |
| GPCHCX | 10Hz | 延续当前已识别、带 SN 的协议，供轨迹和一般工况查看 |
| GPCHC、GPCHCSN | 若无其它消费者，可不重复输出 | 当前平台以 GPCHCX 获取 SN 和质量字段 |
| GNSS 原始、IMU 原始、星历、其它二进制 | 本上传通道没有用途时关闭 | 减少混合流、负载与存储；先确认没有其它应用依赖 |
| 算法内部日志 | 另在惯导配置保持打开 | 精简上传不等于关闭设备诊断日志 |

GPCHCX 的 10Hz 是本平台当前工程建议，不是手册强制频率，也不足以做高频振动频谱分析。需要更高频率时，应另行评估协议、带宽、存储及分析采样要求，不能只提高网页频率。

TCP/UDP_Client1—3 仅支持该手册所述 1Hz 卫导 NMEA，不可用它们代替 Client7 的组合数据回传。RTK 客户端负责“接收差分”，Client7 负责“上传测量”，两者不是同一服务。47.116.139.4:9000 不是 CORS 服务。

保存后检查连接/输出状态，并在质检平台确认最新采样时间继续增长。TCP 连接成功但时间不增长，仍需检查输出协议与解析日志。

### 3.4 让平台回传并显示 10 Hz 低频振动

平台的振动窗复用 GPCHCX 中已有的 `ax/ay/az` 三轴比力，不需要另开一条 IMU 原始流。按以下顺序配置和验收：

1. 在【I/O 设置→TCP/UDP_Client7→连接】记录原值；若正在连接且详细设置不可编辑，短暂断开该 Client7。
2. 连接协议选 `TCP`，远程 IP 填 `47.116.139.4`，端口填 `9000`，勾选【开机自连接】。
3. 在【详细/输出数据】只启用平台所需的 `GPCHCX`，频率选 `10Hz`。本通道不要同时启用 GPCHC、GPCHCSN、RAWIMUA、CORRIMUDATAA、GNSS 原始、星历等重复或未解析输出，除非已确认另有消费者依赖。
4. 保存后重新连接 Client7，确认页面连接/输出状态正常。到【惯导→惯导配置→融合数据设置】保持【实时组合】打开；振动抑制等级先保持普通车辆默认 `2`，不要为了让曲线更平滑直接改到 `5`。该等级会改变设备输出带宽和动态响应，只有在相同工况对照试验及厂商确认后才调整。
5. 打开质检平台，核对设备【最新采样】持续增长；选择最近 15 分钟，在【运行总览】和【惯导分析】分别确认同一份筛选时段振动趋势（动态 RMS、峰值偏差、有效值）以及末端诊断频谱（连续窗约 60 秒、0–4 Hz FFT）。
6. 反向核验：临时停止 Client7 后，平台最新采样应停止增长且振动窗不得用旧数据伪装实时；恢复后应继续增长。完成后保留配置截图和变更时间。

这里的 10 Hz 上限只支持低频载体振动趋势。奈奎斯特频率是 5 Hz，平台进一步将展示带宽保守限制为 0–4 Hz；设备对 10 Hz GPCHCX 输出的抗混叠处理没有在现有手册中明确，未经同频激振实测前，FFT 主频只作趋势观察。轴承、齿轮冲击包络谱通常需要远高于 10 Hz 的专用振动采集，当前链路不能替代。平台使用 1 秒 RMS 作为时域包络，不使用希尔伯特包络谱；后者在当前采样率和设备输出语义下容易产生误导。

## 4. 解决单点定位、漂移：差分接入 + RTK 模式

### 4.1 选一种真实可用的差分来源

**方案 A：设备自带 SWAS SDK 服务仍有效。**

【I/O 设置→RTK 客户端→连接】：连接协议选 `ONE_STEP_FIX`。核对账号状态、到期时间；如服务允许，为当前以 WGS84 记录的应用选 WGS84，点击确定并确认已登录。不能假定服务永久有效，也不要把手册截图中的试用状态当作本机状态。

**方案 B：持有第三方或独立 SWAS CORS 账号。**

【I/O 设置→RTK 客户端→连接】：

| 字段 | 填写方式 |
|---|---|
| 连接协议 | NTRIP（除非服务方明确要求其 TCP 模式） |
| 远程 IP/服务地址 | 账号供应商提供的当前接入地址 |
| 端口号 | 与该账号、坐标基准匹配的当前端口 |
| 源列表 | 点击“获取”，选供应商指定的源节点/mountpoint |
| 用户名、密码 | 该差分账号的凭据，不是 admin/password，也不是平台账号 |
| 确定后状态 | 必须核对已登录及后续实际定位状态 |

手册第 66—67 页的 SWAS IP、端口和源节点是当时示例，不把它们当作已验证的现行账号参数。使用供应商当前配置；不要拿设备 SN、平台管理员账号或 9000 接收端口替代。

若已有正确的串口/网口 RTCM 差分输入，保留其有效链路，不同时添加来源不明、基准不同的第二路差分。

### 4.2 核对融合页中的差分选项

【惯导→惯导配置→融合数据设置】：

- **差分：RTK**，前提是有有效差分输入并计划进行 RTK 工况测试。
- **实时组合：打开**。关闭时内部 GNSS/INS 融合停用，只运行 RTK；车辆参数不再影响纯 GNSS 输出。
- 无差分账号时，暂用“单点”只能用于粗定位/功能检查，不是厘米级修复方案。
- PPP-B2b/HAS-E6 是另外的能力分支；手册描述空旷环境约 20 分钟收敛、水平约 20cm，不能作为即时厘米级替代。是否支持、是否适用要看设备固件和环境。

### 4.3 不只看“已登录”

检查【接收机状态→接收机位置】的类型是否到固定，再看【惯导→惯导状态】GNSS 是否“固定/稳定解定位定向”。差分登录成功不保证卫星几何、多路径、双天线定向也合格。

手册第 54 页的约 1 分钟收敛条件包含较好天空环境、约 25 颗以上卫星等；这不是对任何现场的承诺。室内、窗边、金属棚下、高楼贴近处的问题，不能只靠网页参数消除。天线应尽量置于载体高处、视野开阔，远离干扰源（第 23、47、83 页）。

## 5. 解决未定向：天线数量、接线和基线

### 5.1 对准配置

路径：【惯导→惯导配置→对准配置】（第 56 页）。

| 字段 | 建议 |
|---|---|
| GNSS 天线/使用天线数 | 实际接两根就选双天线；只接一根就选单天线，不能虚选 |
| 对准模式 | 自动 |
| 对准位置 | 自动 |
| 初始时间 | 正常 GNSS 使用时保留默认/不另填，不用它修正平台时段 |

旧固件可能在车辆参数区域显示“使用天线数”。单天线只支持手册所述通用车载、低速车载模式，需要一定行驶速度才能对准。一直静止且只有一根天线，不能靠改某个航向数值获得可靠绝对航向。

### 5.2 双天线现场检查

- GNSS1 接定位主天线，GNSS2 接辅助定向天线，确认线缆与位置关系。
- 两根天线都应有良好天空视野，不能一根在车内、一根在车外。
- 观察两路卫星及定向状态；副天线卫星多不等于已经满足定向精度。
- 手册第 83 页把“能定位不定向”的排查重点放在 GNSS2 接线和搜星；也提示检查主副天线反接。历史无断路/短路位不等于天线安装与信号条件正确。

### 5.3 基线参数

【融合数据设置→基线配置】：只有已经测量且两天线相对位置刚性固定时，才打开并填写“基线长度/误差”。第一格为双天线相位中心距离，第二格为实际测量误差，单位 m；不能填 0 或凭空填理想精度。

【车辆参数设置→GNSS 定向基线与车辆坐标系夹角】：按“主天线指向辅天线”的向量填写。车辆坐标 X 向右、Y 向前、Z 向上；基线水平时，下例可帮助核对 Z 角，但不是本机实测值：

| 实际布置 | 基线朝向 | X/Y/Z 角示例 |
|---|---|---|
| 主天线在后，辅天线在前 | 车头方向 | 0 / 0 / 0° |
| 主天线在左，辅天线在右 | 车右侧 | 0 / 0 / −90° |
| 主天线在右，辅天线在左 | 车左侧 | 0 / 0 / +90° |

高度差、斜装或其它安装方式需按实际三维关系计算，不能只填一项 Z 角。低速车载模式不自动修正该基线安装角误差，因此必须特别准确（第 58—59、70 页）。

## 6. 解决姿态/参考点问题：安装角和杆臂

路径：【惯导→惯导配置→融合数据设置/车辆参数设置】（第 49—60 页）。

### 6.1 推荐的起始选择

| 参数 | 本轮建议 | 适用条件与限制 |
|---|---|---|
| 姿态参考系 | 车体姿态/车辆姿态 | 用于车辆运行视图；必须先把安装角配正确 |
| 输出参考点位 | 天线相位中心 | 初期排查最易与 GNSS 定位核对；若项目已有明确参考点，先保持原定义 |
| IMU 位置 | 测准杆臂后再选 | 手册要求 IMU-GNSS 杆臂达到厘米级测量 |
| 目标点 | 没有明确需求不选 | 需要另填以定位天线为原点的目标点杆臂 |
| 位置记忆 | 当前无车库重启需求可关闭/保持关闭 | 不是静止锁点；不能修复首次初始化或 GNSS 漂移 |
| 算法日志保存 | 打开 | 保留厂家诊断依据；按第 2.8 节，不为排障先关闭日志 |
| 振动抑制等级 | 2 | 手册默认 40Hz；先修正导航状态和安装问题 |

切换输出参考点本身会改变位置定义；初始化/组合与卫导状态下还可能使用不同参考点。记录变更时间，不将变更前后的坐标差自动当作车辆移动。

### 6.2 安装角：不能直接把横滚 −90°“改成 0°”

【惯导到车辆坐标系夹角】采用手册定义的右手旋转，旋转顺序 Z-X-Y，但网页三格按 X、Y、Z 填写。

- 只有主机标准水平安装、铭牌 Y 指向车头、Z 向上，才填写 `0 / 0 / 0°`。
- 主机侧放、竖装或朝向相反时，先根据铭牌箭头与车体坐标测量/确认实际安装角。没有安装照片和方向关系，无法可靠给出本机三个数字。
- 历史 −90.25° 与 X 轴约 1g 有一致性，可能就是主机侧放，不可把它当作传感器坏了或凭曲线反向加一个 90°。
- 配置误差是实际不确定度，不是精度愿望。手册注明三个角度误差均 ≤0.1° 时，算法不再修正安装角误差；不得为“提高精度”随意填 0。

姿态参考系设置**只变换姿态角**，不会自动把所有三轴 IMU 数据变成车体线加速度或去掉重力。不要逐轴减 1g。若需去重力、车体系 IMU，必须明确相应协议和固件语义，再适配平台解码，不能直接换协议让当前服务猜测。

### 6.3 杆臂：区分原点和终点

统一按车辆坐标填写：X 右为正、Y 前为正、Z 上为正，单位 m。

| 字段 | 原点 → 终点 | 说明 |
|---|---|---|
| 惯导到 GNSS 定位天线杆臂 | IMU 中心 → GNSS1 相位中心 | 例如主天线在主机右 0.20m、前 0.50m、上 0.80m，才可填 +0.20/+0.50/+0.80 |
| 定位天线到后轮中心杆臂 | GNSS1 相位中心 → 后轴中心 | 若天线位于后轴中心前 0.50m、上 1.00m且无横向偏移，则填 0/−0.50/−1.00 |
| 目标点杆臂 | GNSS1 相位中心 → 所需目标点 | 只在选择目标点参考时需要 |
| 轮距 | 左右轮距 / 前后轴距 | 实测，不照抄手册 1.6/2.7 或截图 1.6/2.6 |

上述数字仅演示正负号，不能直接用于本机。IMU-GNSS 杆臂配置误差均 ≤0.01m 时，算法不再估计修正该杆臂误差（第 60 页）；填一个很小的误差并不会使卷尺测量变精确。

GPCHCX 第 40—43 字段是安装角/基线角的补偿小角，不含大安装角（第 12 页）。服务器看到这些值为 0，不足以判断网页是否已填侧装 90°。

## 7. 工作模式与首次标定：当前一直静止应怎么处理

【惯导→惯导配置→车辆参数设置→工作模式】：根据实际载体运动模型和正常运行速度选择，不按本次“停着没动”选择。

| 实际用途 | 模式 | 手册标定要点 |
|---|---|---|
| 普通车辆，正常运行速度在 15km/h 以上 | 通用车载 | 第 72 页描述固定解定向、空旷搜星、含左右转弯及加减速，避免倒车，通常 5—10 分钟 |
| 实际低于 15km/h、单一前/后轮转向的小车 | 低速车载 | 第 72 页描述 1.8—15km/h、固定解定向、转弯及加减速，通常 5—10 分钟 |
| 可斜行/横移的多轮转向 AGV | 多轮转向低速车载 | 第 72 页要求直线前进、原路倒车，禁止套用通用车的转弯/掉头标定方法 |
| 本轮确实是非车辆固定台架/机械臂姿态试验 | 可评估组合 AHRS | 第 58 页说明无需车辆动态标定，第 72 页列静止流程；仍需正确安装参数、定向及相应差分条件 |

**如果选的是通用/低速车载，并且首次手动标定未完成，一直静止几小时不等于完成了首次跑车标定。** 已经完成正确首次标定且安装没变时，后续启动才是手册所说约 1 分钟的初始化。

【融合数据设置→标定模式】：真实车辆通常选“手动标定”。“不标定”是精确使用人工配置参数、不再估计补偿安装误差的模式，适用于特定难以标定载体；不能把它当作消除报警或跳过首次标定的万能按钮。

如果目前只是桌面静止演示，先解决双天线与差分；可与厂商确认当前固件的 AHRS 静止流程。不要仅为显示组合状态而将以后要上车的配置永久改成非车载模型。切回车辆用途时重新配置并按该车标定。

参数全部确认后保存，再刷新、重新进入页面检查确实保存成功。手册第 71 页明确提示车辆参数保存后需重新标定，因此不要在完成标定后无意义地反复按保存。主机/天线位置或朝向改变也需重新处理标定。

观察【惯导状态】：手动标定完成进度 100%、INS 进入组合导航；双天线 RTK 正常工况下，GPCHCX 状态应能达到 `42`（高 4=固定解定向，低 2=组合导航）。该值是验收观察结果，**不是手动填写的状态参数**。

## 8. 轮速中断：先判断是否真正接了轮速

路径：【惯导→里程计/里程计设置】（第 64、78—81 页）。

### 未接 CAN 轮速

取消车辆速度、左轮速、右轮速、方向盘转角、档位中没有真实输入的勾选。不要发送“恒定 0”伪造车辆静止；以后真实运动会被错误约束。轮速是辅助输入，没有轮速也可以在条件满足时使用 GNSS+IMU。

取消未用项是正确配置，但不承诺所有固件都会消除报文轮速中断位；若固件仍上报，应记录为未配置轮速的预期诊断，不能只为隐藏该位伪造数据。

### 已接 CAN 轮速

依照车辆 DBC/实际报文逐项核对数据格式 Intel/Motorola、数据 ID、标准/扩展帧、起始位、位长度、有无符号、比例系数、偏移量、总线速率，以及真实存在的信号勾选。

手册有几处特别容易填错：

- ID 输入用十进制。例：0x19FF402D 对应 436158509；这只是手册例子，不是本车 ID。
- 第 80 页的“比例系数”按所述界面规则通常填真实比例的倒数。例：真实量=raw×0.01，网页示例填 100，不填 0.01。必须核对当前固件。
- 对真值=k×raw+b，手册该界面偏移填 −b；对真值=(raw+b)×k，填 −k×b。不要把普通 DBC 的 offset 原样复制而不核验。
- DBC 起始位与网页的位编号可能不同。手册第 81 页给出特定示例的 n=N+7−2×(N%8)；第 80 页又展示已给起始位直接填写。不能对所有 Intel/Motorola 来源盲目套公式，需要拿实际帧做已知速度核对。
- 第 60 页轮速精度正文写 m/s，第 57 页截图及第 71 页写 km/h，存在文档不一致；填前按当前固件标签和厂商确认。精度栏不是车辆当前速度栏。
- 里程计延迟未知时手册建议保留默认 20ms（第 60 页），不要为消除延迟告警随意填 0；实际已测值优先。

验收应同时包含安全静止时实际轮速接近 0，以及安全运动时速度、左右轮、转角与档位一致。缺少 DBC/协议时不提供本车可直接复制的 CAN 数字。

## 9. 降噪及不应误改的设置

【惯导配置→融合数据设置→振动抑制等级】默认 2，手册第 51 页给出 40Hz，适合普通道路车辆。3—5 可增强低通抑制，但会降低动态响应、增加延迟；5 对应 5Hz。当前没有证据需要设到 5。

先修复 RTK/定向/组合/安装，再在相同条件下对比噪声与响应。该参数不能解决 GNSS 多路径、错误杆臂、CORS 授权失效或 TCP 断流，也不能保证静止每轴数值都严格为零。

不要做下列“表面修复”：

- 不把“位置记忆”当作静止锁定开关；手册没有给出可用于当前问题的一键静止强制归零配置。
- 不用初始时间把旧采样伪装成当前采样。
- 不设置坐标偏移来让漂移轨迹对齐地图。高德 GCJ-02 是平台显示转换，设备原始坐标基准要保持明确；不要在设备再做一次 GCJ-02 显示偏移。
- 不为了追求固定状态选与实际差分来源不一致的坐标基准。
- 不用恢复出厂、清星历、关闭诊断日志作为第一步。
- 底图网络、时间筛选、异常隔离和服务器 80%/75% 清理策略属于平台问题，不由设备网页这些参数修复。

## 10. 建议执行顺序、验收及回退

建议顺序：备份与拍照 → 恢复持续上报 → 核对移动网络/差分登录 → 检查双天线定向 → 完成安装角/杆臂/工作模式 → 保持实时组合打开 → 保存并按载体标定 → 静止复测 → 必要时再调振动等级。

本项目建议在变更后连续记录 10—15 分钟静止数据；这个时长是排查建议，不是厂商强制标准。每次记录 SN、固件、变更项、北京时间和是否移动；涉及车辆参数的修改应集中确认后保存，避免反复触发标定。

| 检查层 | 通过条件 |
|---|---|
| 网络与回传 | Client7 有连接/输出，平台最新有效采样时间持续增长，而非仅 TCP 接收字节增加 |
| 差分 | 真实差分接入且环境合格时达到固定解；不能只用 Age=0 或已登录证明 |
| 定向 | 双天线工况显示定向，航向与实际朝向一致 |
| 组合 | 手动标定流程完成，INS 为组合导航；RTK 双天线正常时观察到 42 |
| 车体姿态 | 水平车体的俯仰/横滚与实测倾角相符；若载体倾斜，不要求强制为 0 |
| 静止测量 | 查看原始位置、速度和标准差是否改善，不能只看平台过滤后“里程为 0” |
| 轮速 | 已接则稳定收到并与实际运动一致；未接则不伪造输入 |
| 配置持久化 | 重新进入页面确认已保存；在安全条件下重启后检查自连接和初始化 |

异常过滤仍然保留；新数据不自动继承旧历史区段的静止假设。参数变化只影响之后的观测，不能把历史坏测量“修回真实值”。若改了输出坐标基准、参考点或协议，需同时记录平台元数据/适配需求，不能把不同定义直接混算。

回退使用本机、同固件版本的配置备份；安装位置没变才考虑对应旧标定文件，恢复后复核状态，必要时重新标定。未来多设备可复用网络输出等通用配置，但 SN、安装角、杆臂、轮距及标定结果需逐机确认，不盲目批量导入同一标定。
