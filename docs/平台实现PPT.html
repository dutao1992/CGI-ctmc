FRAME MATCHING
# 正则匹配：$ 或 # 开头，*校验和结尾

  rb'([$#][A-Z][A-Z0-9]+,[\x20-\x7e]{1,4096}?'
  rb'\*[0-9a-fA-F]{2,8})\r?\n'
)

# 双校验：XOR（GPCHC/GPCHCX）
#        CRC-32（#AGRICA 二进制）

    if frame[:1] == b'$':

        return value == int(check, 16)

03 / INGESTION

数据入库：游标增量扫描

SCAN LOOP

每 10 秒扫描原始日志目录，游标记录已读字节偏移。断线重连、历史补录均自动追赶。

入库流水线（每条报文）

① FRAME 正则 → checksum 校验
② parse() → 46 字段解码 + 范围检查
③ INSERT OR IGNORE → points 表（主键去重）
④ write_assessment() → point_quality 表
⑤ rebuild_rollup_buckets() → 60s/600s 聚合
⑥ 更新 devices 表元数据 + 清除查询缓存
KEY DESIGN DECISIONS

SN 即身份

设备 SN 作为主键，公网 IP 变化不拆分设备。GPCHCX 字段内携带 SN；GPCHC 需预绑定（当前未接入）。

时间戳去重

主键 (device_id, t, protocol)，同一时刻同一设备同一协议只保留一条，防止日志文件轮转重复读。

时钟过滤

拒绝 t > now+300s 或 t < 2010-01-01 的报文，防设备时钟异常污染数据库。

05 / QUALITY FILTER

质量过滤框架：版本化可逆隔离

原则1

不修改原值

points 表永远保存接收到的原始解码值；point_quality 存储字段级 mask 位域，两表分离。

原则2

按字段隔离

同一采样中 lat/lon 异常不影响 IMU 字段；位置过滤不清零角速度。各字段独立开关。

原则3

版本化决策

过滤 VERSION=2 写入 point_quality.version；版本不匹配时前端明确提示，聚合显示为"待判定"。

过滤原因分类（共 12 种）

不可用 (unavailable)

  • invalid_navigation：导航初始化中 / nav_mode=0
  • heading_unavailable：定向未就绪（fix_mode 不支持）
  • course_unavailable：静止或低速时航迹角无意义

离群 (anomaly)

  • stationary_position：静止期位置偏离锚点 >15m
  • stationary_velocity：静止期水平速度 >0.3 m/s
  • stationary_gyro/accel/attitude：静止期 IMU 离群
  • position/altitude_uncertainty：标准差超限
06 / STATIONARY FILTER

静止过滤算法：MAD 稳健统计

PROFILE FITTING

用一段已知静止时段拟合设备的"正常静止基线"：

# 1. 中位数作锚点（抵抗 GNSS 漂移极值）
center = median(values)

# 2. MAD = 中位绝对偏差（稳健 σ 估计）
mad = median(|x_i - center|)

# 3. 门槛 = max(工程底线, 6×1.4826×MAD)
limit = max(floor, 6 × 1.4826 × mad)
# 1.4826 = 正态分布下 MAD → σ 的换算系数
# 6σ ≈ 99.9997% 置信区间

工程噪声底线（防止过拟合）

字段底线字段底线
位置半径10 m速度0.3 m/s
高程10 m角速度0.15 °/s
比力0.02 g姿态1°
ACTIVE CONTEXT CAPS

转为"持续静止"后，额外加盖上限防漂移训练：

⚠️ 硬上限约束

  • 位置半径：≤ 15 m
  • 高程偏差：≤ 15 m
  • 位置标准差：≤ 5 m
  • 高程标准差：≤ 8 m

📋 上下文不可篡改

已冻结的 quality_contexts 记录以内容哈希（SHA256[:20]）为主键，不可覆盖、不可追溯修改。关闭需要填写原因，写审计日志。

07 / AGGREGATION

聚合算法：分层等时桶 + 峰值保护

TWO-LEVEL ROLLUP
层级分辨率适用窗口数据源
原始~10 Hz< 6 小时points 表直读
一级60 秒6h – 2 天RollupBuilder
二级10 分钟> 2 天QueryCombiner 合并一级
BUCKET CONTENT

每个时间桶存储（以 JSON 形式）：

  • 每个指标的 min / max / sum / count / last
  • 首末采样快照（first/last endpoint）
  • 轨迹点压缩数组（首末 + 关键节点）
  • 行程区段列表（moving/stopped/stationary）
  • 时间断档列表（gaps）
  • 质量分组统计（version, mask, reasons, count）
ANOMALY PRESERVATION

✅ 峰值不丢失

min/max 随点累计，60 秒内的单点冲击体现在桶的 max 上。前端同时绘制均值曲线 + min/max 包络带。

✅ 过滤先于聚合

project() 在每条点被 RollupBuilder.add() 前调用；被 mask 的字段跳过，不进入均值，也不污染 min/max。

✅ 事件独立于聚合

事件检测在逐条原始采样层面运行（实时：入库时；离线：逐行 CSV），与聚合路径完全分离。

STATE MACHINE

⏱️ 持续时长合并（dwell）

超速/姿态等事件须持续 dwell_s 秒后才生成记录；冲击事件 0.1 s 即触发（单次冲击不应被忽略）。

🔄 连续事件延伸

同类事件间隔 < gap_s 时延伸同一条记录（更新 end/peak/samples），不新建重复事件。

📦 规则版本号

每次修改规则，rules.version 自增。历史事件保留当时版本，不会因规则调整而追溯修改。

QUERY STRATEGY

🧠 智能分辨率选择

窗口 <6h → 原始；6h-2d → 60s 聚合；>2d → 10min 聚合。首尾不整齐桶回退原始，保证边界精度。

⚡ 内存查询缓存

最多缓存 16 个查询结果（OrderedDict LRU），近实时数据 10s TTL，历史数据 60s TTL。版本号变更时立即失效。

🛡️ 并发保护

查询槽位 BoundedSemaphore(2)，防止长时间范围查询耗尽连接。聚合索引未就绪时拒绝 >100万条原始回退。
