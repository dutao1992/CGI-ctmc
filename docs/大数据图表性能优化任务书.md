# 大数据图表性能优化任务书

## 目标

让 24 小时及更长时间范围不再逐条由 Python 处理全部原始采样；在保留字段过滤、异常峰值包络、轨迹断点和质量统计语义的前提下，使查询结果能在数秒内返回，并让 12 组 ECharts 图表分批绘制而不长时间阻塞页面。

## 完成标准

- 24 小时查询使用持久化分钟聚合层，服务端不再扫描约 82 万条原始记录；生产热查询目标不超过 1 秒，首次查询目标不超过 3 秒。
- 长窗口仍返回每个字段的有效均值、最小值、最大值，原有异常峰值、字段隔离、缺测断线和设备隔离测试不退化。
- 相同查询在短 TTL 内命中服务端缓存；实时尾部保持从原始采样读取，不能用过期缓存冒充最新数据。
- 前端按时间跨度选择绘图桶数，12 组图表分帧绘制，并显示聚合分辨率与服务端耗时。

## 禁止事项

- 不修改 TCP 9000 接收器、原始日志格式、现有认证权限和 80%/75% 存储策略。
- 不物理改写或覆盖原始采样、隔离原值、事件和审计记录。
- 不用简单丢点替代峰值保留；最小值和最大值必须继续覆盖桶内有效异常峰值。
- 不通过删除测试、放宽断言、跳过测试或提高超时阈值制造性能“通过”。

## 执行步骤

1. 记录生产数据量和现有 COUNT/聚合耗时，冻结 1 小时短窗口行为作为回归基线。
2. 新增可重建的 60 秒派生聚合表；保存字段统计、质量计数、运动摘要、轨迹断点和桶边界，原始表仍是唯一事实来源。
3. 查询跨度超过 6 小时时读取完整分钟桶，首尾不足一分钟的部分仍读原始采样；聚合覆盖不完整时自动回退原始查询。
4. 新增线程安全、容量受限的 TTL 查询缓存；质量重算、数据清理和迟到采样必须使相关缓存失效。
5. 前端自适应桶数并缓存图表转换结果，12 组图表分帧渲染，页面显示读取来源、分辨率和耗时。
6. 在服务停止、9000 接收器继续记录的部署窗口备份数据库并回填派生聚合；失败自动恢复上一 release。

## 验收方法

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_map.cjs
python3 analysis/benchmark_query.py --db /srv/ctmc-vehicle/data/vehicle.sqlite --device 6094510 --hours 1 24
```

判定：全部测试无跳过；24 小时结果标记 `source=rollup` 且第二次查询 `cache_hit=true`；原始总数、质量分类数及峰值测试一致；部署后 `/healthz`、公网 `/vehicle/`、数据库 `quick_check` 和最新采样持续增长。

## 风险

- 派生聚合回填会短时占用 CPU 和增加少量数据库空间，因此只在停止解析服务后执行，TCP 接收器保持运行。
- 分钟聚合会把长窗口曲线的时间定位精度降低到一分钟以内；响应中必须明确 `source_resolution_s=60`，短窗口继续使用原始数据。
- SQLite 版本较旧，迁移只能使用兼容的表和事务语法；不能依赖新版本窗口函数或扩展。

## 回滚方案

部署前保留 SQLite 在线备份和上一 release 链接。新版本健康检查、测试或性能验收任一失败时，重新指向上一 release 并重启 `ctmc-vehicle.service`；新增聚合表属于可删除派生数据，旧版本会忽略它，原始采样和接收器无需回滚。
