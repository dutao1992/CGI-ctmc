# 历史数据运动、静止与异常点审计优化任务书（2026-09-02）

## 目标

以生产库原始 `points` 和原始报文时间为事实源，消除不可能的车辆速度和显著位置漂移，让历史回算与后续实时采集统一使用简单、可复核的三轴冲击阈值规则。

## 完成标准

- 全历史逐点计算 `|√(ax²+ay²+az²)-1|`；`≤0.005 g` 判静止、`>0.005 g` 判运行，导航模式/速度/航迹角不改变结果。
- 运行和静止期间的有效位置均保留绘制；只对无法由相邻速度解释的显著单步位置跳变隔离经纬度，并继续隔离超过 130 km/h 的失真导航解。
- 用户参考时段 12:28—12:36（运行）、12:36—12:39（静止）、12:39—12:45（运行）和 12:48 移动均由只读审计脚本输出状态分布，不能替代逐点阈值。
- Python/Node 测试通过；生产回算原始摘要不变、质量待判定 0、60 秒/600 秒聚合覆盖一致，展示桶减少以降低曲线重绘时间。

## 禁止事项

- 不修改或删除 `points`、原始日志和 TCP 9000 接收器；异常只写版本化 `point_quality`、静止上下文和可重建聚合。
- 不把导航初始化、定向未就绪、低速航迹角本身作为剔除理由；不补零、不插值、不伪造车辆状态。
- 不用速度、导航模式或旧持续静止上下文覆盖三轴阈值；不为通过测试放宽断言、跳过测试或改写历史事实。

## 执行步骤

1. 只读统计全历史速度上限、位置跳变、状态模式、分钟级运动/静止证据，并回读所有候选原始点。
2. 将质量算法升级为 v5：加入三轴合成峰值偏差 0.005 g 的唯一运动判定、130 km/h 物理有效性和显著位置跳变隔离；旧静止上下文仅保留审计。
3. 用用户提供的四个参考时段执行只读审计，确认状态分布和异常位置跳变，不把参考时段硬编码为过滤事实。
4. 以每批 20,000 点的有界事务重建质量投影与两级聚合，验证最高有效速度、运动/静止分段、轨迹和参数曲线。
5. 备份后部署；保持 TCP 接收器运行，验收服务、定时器、健康探针和网页。

## 验收方法

- `python3 -m unittest discover -s tests -v`
- `node --check static/app.js && node --check static/map.js && node --test tests/test_map.cjs`
- `git diff --check` 与全模块 `py_compile`。
- 生产副本比较回算前后 `points` 行数与逻辑 SHA-256；查询全历史 `summary.max_kmh`、四个参考时段状态分布、显著位置跳变计数和聚合覆盖。
- 正式页检查 24 小时最高有效速度、静止轨迹、剔除原值和控制台错误；核对 TCP 9000 PID 未变。

## 风险

- 三轴阈值只表示当前采样的冲击/比力偏差；缺轴时状态为未知，不能把未知强行当静止或运行。
- GNSS 漂移可能同时污染速度和位置；位置跳变检查只隔离明显单步跳点，不影响连续的 130 km/h 以下真实车辆运动。
- 全量回算约 200 万点并重建聚合，必须在独立接收器持续落盘、解析/API 短暂停止且有可校验备份的窗口执行。

## 回滚方案

上线前生成唯一 SQLite 备份并验证 `quick_check` 与原始摘要；任何原始摘要变化、待判定不为 0、聚合覆盖不一致、服务不健康或网页关键统计倒退时，停止新 API/解析进程，将 `current` 指回上一 release，并用备份恢复派生质量/聚合后追平停机期间原始日志。绝不以旧库覆盖新增原始采样。
