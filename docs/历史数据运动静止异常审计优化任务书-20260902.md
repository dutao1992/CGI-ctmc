# 历史数据运动、静止与异常点审计优化任务书（2026-09-02）

## 目标

以生产库原始 `points` 和原始报文时间为事实源，消除不可能的车辆速度和静止后的定位漂移，补齐运行结束后自动进入静止状态的生命周期，并让历史回算与后续实时采集使用同一套版本化规则。

## 完成标准

- 全历史 60 秒聚合逐桶审计并回读异常原始点；物理有效速度不超过用户确认的 130 km/h，07:43:42—07:43:44 的 23 个导航解算异常点不再进入有效速度、轨迹和里程。
- 2026-09-02 07:57:05.7 起按 v4 历史回放证据及用户复核确认静止；静止锚点外 15 m 或水平定位标准差超过 5 m 的经纬度被隔离，IMU、姿态、导航状态和原始报文仍保留。
- 自动静止进入必须同时满足持续时间、低速中位数、稳定陀螺/比力和位置非连贯位移约束；单点速度归零、等速直行、短暂停车、GNSS 跳变不得误触发。已进入静止后继续使用现有多证据运动退出规则。
- Python/Node 测试数不低于当前 66/17，跳过 0；生产副本回放、原始摘要不变、质量待判定 0、60 秒/600 秒聚合覆盖一致。

## 禁止事项

- 不修改或删除 `points`、原始日志和 TCP 9000 接收器；异常只写版本化 `point_quality`、静止上下文和可重建聚合。
- 不把导航初始化、定向未就绪、低速航迹角本身作为剔除理由；不补零、不插值、不伪造车辆状态。
- 不用单一速度、单一 IMU 安静或单个位置点确认静止；不为通过测试放宽断言、跳过测试或改写历史事实。

## 执行步骤

1. 只读统计全历史速度上限、位置跳变、状态模式、分钟级运动/静止证据，并回读所有候选原始点。
2. 将质量算法升级为新版本：加入 130 km/h 物理有效性规则；加入基于 1 Hz 有界窗口的自动静止进入检测；扩展静止上下文审计和安全关闭。
3. 安装 09-02 07:57:05.7 经用户复核确认的活动静止上下文；用历史回放评估其他自动候选，但只落地满足完整多证据条件的区间。
4. 以每批 20,000 点的有界事务重建质量投影与两级聚合，验证里程、最高有效速度、运行/静止分段、轨迹和参数曲线。
5. 备份后部署；保持 TCP 接收器运行，验收服务、定时器、健康探针和网页。

## 验收方法

- `python3 -m unittest discover -s tests -v`
- `node --check static/app.js && node --check static/map.js && node --test tests/test_map.cjs`
- `git diff --check` 与全模块 `py_compile`。
- 生产副本比较回算前后 `points` 行数与逻辑 SHA-256；查询全历史 `summary.max_kmh`、09-02 08:02 后剔除计数、上下文边界和聚合覆盖。
- 正式页检查 24 小时最高有效速度、静止轨迹、剔除原值和控制台错误；核对 TCP 9000 PID 未变。

## 风险

- 自动静止过敏会把交通灯停车误作长期静止；通过至少 120 秒多证据确认、候选起点回溯和运动自动退出降低影响。
- GNSS 漂移可能同时污染速度和位置；物理上限只隔离明显失真的导航解，不影响 130 km/h 以下真实车辆运动。
- 全量回算约 200 万点并重建聚合，必须在独立接收器持续落盘、解析/API 短暂停止且有可校验备份的窗口执行。

## 回滚方案

上线前生成唯一 SQLite 备份并验证 `quick_check` 与原始摘要；任何原始摘要变化、待判定不为 0、聚合覆盖不一致、服务不健康或网页关键统计倒退时，停止新 API/解析进程，将 `current` 指回上一 release，并用备份恢复派生质量/聚合后追平停机期间原始日志。绝不以旧库覆盖新增原始采样。
