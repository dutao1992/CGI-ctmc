# 持续静止自动退出优化

## 目标

根据《聚合算法数据质量评估》收敛唯一中等风险：操作员漏关 `confirmed_stationary_active` 时，平台应在不改写原始采样、不放松质量过滤的前提下，阻止真实运动被长期归入静止异常。

## 完成标准

1. 管理员能在数据质量页填写关闭时间和原因；权限、CSRF、最新采样边界和审计均由服务端强制。
2. 只有高质量组合导航下的持续位移才能自动关闭；单点跳变、卫导未定向、低质量定位和速度尖峰均不得触发。
3. 自动关闭确认点起恢复普通运动规则，关闭证据可从 `audit` 和查询返回的 `context.closure` 复核。
4. Python/Node 测试数不得低于改前的 53/11，跳过数为 0；聚合版本、原始表和质量版本保持不变。

## 禁止事项

- 不修改 `points` 原值、TCP 9000 接收器、60秒/10分钟聚合算法或现有容量策略。
- 不用单个速度、单个坐标跳变或“IMU 看起来安静/运动”直接改变用户确认事实。
- 不让页面直接执行历史补关；早于最新采样的关闭必须走运维回算路径。
- 不跳过测试、不放宽既有断言、不用 mock 替代质量判定对象。

## 执行步骤

1. 冻结聚合、字段投影和原始证据链，记录 53 项 Python、11 项 Node 基线。
2. 在 `vehicle/quality.py` 增加纯状态检测器和审计化自动关闭；在入库写质量判断前使用原始采样确认。
3. 在 `vehicle/server.py` 增加管理员关闭接口，只允许从设备最新采样之后截断。
4. 在数据质量页显示自动保护判据、自动关闭结果和管理员操作入口。
5. 增加正向与反向测试，更新生命周期说明和本评估文档。

## 验收方法

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_map.cjs
```

反向验收必须证明：单次高质量跳点不关闭、持续卫导漂移不关闭、非管理员不能关闭、空原因和历史边界被拒绝。正向验收必须证明：满足全部判据后自动审计并从确认点恢复普通速度；管理员关闭后的下一条运动采样不再带静止上下文。

## 风险

- 严格判据会晚于真实起步数秒，且未进入组合导航时不会自动关闭；这是避免漂移误撤销用户事实的有意取舍。
- 自动确认前的候选样本仍按静止证据保留，不自动重写历史；若需要修正已发生区间，必须显式补关和回算。
- 页面关闭时间依赖操作员填写的北京时间，服务端以最新采样边界和当前时间双重限制。

## 回滚方案

若出现误关闭，立即回滚应用 release；数据库中的关闭记录不会被旧部署清单重新打开，应由运维根据原始证据创建新的、起点明确且不重叠的持续静止上下文。若仅需停用自动检测，可回滚 `vehicle/quality.py` 与 `vehicle/store.py`，保留已写审计和已截断历史区间；不得用旧数据库覆盖继续接收的采样。
