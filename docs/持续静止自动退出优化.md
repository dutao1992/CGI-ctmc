# 持续静止自动退出优化

## 目标

根据《聚合算法数据质量评估》收敛唯一中等风险：操作员漏关 `confirmed_stationary_active` 时，平台应在不改写原始采样、不放松质量过滤的前提下，阻止真实运动被长期归入静止异常。2026-08-28 新增低速验收条件：测试载体为最高约 `0.5m/s`、连续路线不少于 50m 的小推车，可进入组合导航。

## 完成标准

1. 管理员能在数据质量页填写关闭时间和原因；权限、CSRF、最新采样边界和审计均由服务端强制。
2. 自动退出分为互不放宽的两条路径：组合导航低速小推车路径，以及允许卫导/组合导航但要求更高速度、位移、定位质量和里程一致性的车辆路径。单点跳变、低质量定位、原地往返漂移和速度尖峰均不得触发。
3. 完整证据窗确认后，从候选起点恢复普通运动规则；关闭证据可从 `audit` 和查询返回的 `context.closure` 复核。
4. 小推车以 `0.5m/s` 直行时，在离锚点至少 30m 后连续满足低速条件 15 秒、净位移至少 8m、轨迹有效率至少 50% 即自动退出；50m 路线足够完成验收。
5. 车辆路径要求速度不低于 `1m/s`、连续 10 秒/20 点、水平定位标准差不大于 5m、净位移至少 25m、轨迹有效率至少 65%，且坐标净位移为速度积分的 65%—135%。
6. Python/Node 测试数不得低于改前的 62/14，跳过数为 0；聚合版本、原始表和质量版本保持不变。

## 禁止事项

- 不修改 `points` 原值、TCP 9000 接收器、60秒/10分钟聚合算法或现有容量策略。
- 不用单个速度、单个坐标跳变或“IMU 看起来安静/运动”直接改变用户确认事实；不得把卫导车辆路径的高速度门槛降到小推车速度，也不得接受单点定位。
- 不让页面直接执行历史补关；早于最新采样的关闭必须走运维回算路径。
- 不跳过测试、不放宽既有断言、不用 mock 替代质量判定对象。

## 执行步骤

1. 冻结聚合、字段投影和原始证据链，记录当前 62 项 Python、14 项 Node 基线；确认线上活动上下文未固化旧自动退出参数，因此无需数据库迁移。
2. 在 `vehicle/quality.py` 保留最低 `0.15m/s` 的组合导航小推车路径，并增加卫导/组合导航车辆路径；车辆路径同时检查定位状态、速度、水平速度向量、连续位移、路径效率和速度积分一致性。
3. 在 `vehicle/server.py` 增加管理员关闭接口，只允许从设备最新采样之后截断。
4. 在数据质量页显示自动保护判据、自动关闭结果和管理员操作入口。
5. 增加正向与反向测试，更新生命周期说明和本评估文档。

## 验收方法

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_map.cjs
```

反向验收必须证明：单次高质量跳点不关闭、卫导模式下 `0.5m/s` 位移不走车辆路径、组合导航下原地往返的低速轨迹不关闭、非管理员不能关闭、空原因和历史边界被拒绝。正向验收必须证明：`0.5m/s` 组合导航小推车和 `3m/s` 卫导车辆分别满足自己的完整判据后自动审计，并从候选起点恢复普通速度；管理员关闭后的下一条运动采样不再带静止上下文。

## 风险

- 判定仅在离锚点至少 30m 后开始，按 `0.5m/s` 与 15 秒/8m 条件预计在总行程约 38—45m 时关闭；50m 路线余量有限，测试应尽量连续直行且不在中段停顿。
- 未进入组合导航时，低速小推车路径不会关闭；只有达到车辆路径全部强判据的卫导数据才会关闭。两条路径都拒绝非 RTK 固定/浮点定位。
- 自动确认是回顾式证据窗：确认后会重算候选起点以来的质量投影和相关聚合桶，避免丢失行程开头 10—15 秒；原始采样不改写。
- 页面关闭时间依赖操作员填写的北京时间，服务端以最新采样边界和当前时间双重限制。

## 回滚方案

若出现误关闭，立即回滚应用 release；数据库中的关闭记录不会被旧部署清单重新打开，应由运维根据原始证据创建新的、起点明确且不重叠的持续静止上下文。若仅需停用自动检测，可回滚 `vehicle/quality.py` 与 `vehicle/store.py`，保留已写审计和已截断历史区间；不得用旧数据库覆盖继续接收的采样。
